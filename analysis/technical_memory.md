# Technical Memory: Milei Climate Narratives Project

**Purpose of this document:** a complete, step-by-step account of how the narrative analysis of Javier Milei's speeches was actually built and executed — from project setup through the current state of the coded corpus — so that any researcher (or any future agent) can understand the full process without having to reconstruct it from scattered files. Nothing below is summarized away: every codebook iteration, every coding batch, every audit and correction is described in the order it happened, with the file paths and counts involved. Dates are taken from file contents, frontmatter, and audit notes wherever the project recorded them explicitly; where only a file's modification date is available, this is noted.

This document is itself a piece of project documentation and should be updated (not rewritten) as the project continues — new coding batches, new codebook versions, or new audits should be appended to the relevant section.

---

## 0. Project origins and setup

The project began from a proposal document, `implementation_plan.md`, written before any research work had started. It proposed a directory structure (`docs/`, `data/`, `analysis/`, `workflows/`) and a three-stage "agent team workflow" — the idea that different phases of the research (methodology design, data collection, analysis) would be handled by separate, specialized instruction sets ("agents") rather than one continuous undifferentiated process. The plan named these **The Methodologist** (Phase 1), **The Data Collector** (Phase 2), and **The Narrative Analyst** (Phase 3), and flagged three open questions for the researcher: where to store the project on the local machine, how to ingest existing materials (a Google Doc abstract, methodology PDFs, a seed spreadsheet of sources), and whether the initial deductive coding categories already existed or needed to be derived from the methodology PDFs by the Methodologist.

The three researchers on the project are Germán Bersalli, Elizabeth Mohle, and Juan Ignacio Arroyo (per `CLAUDE.md`). Once the plan was approved, the actual directory structure was built with one small deviation from the proposal: the plan's Phase 2/Phase 3 ordering in its workflow filenames (`1_data_collector.md`, `2_methodology_assistant.md`) was corrected in the built project to the logically correct order — `workflows/1_methodologist.md`, `workflows/2_data_collector.md`, `workflows/3_narrative_analyst.md` — since methodology has to exist before data collection is scoped, and data has to exist before it can be analyzed. This ordering (methodology → data → analysis) is what the project actually followed throughout.

A companion document, `skills/SKILLS_ANALYSIS.md`, was written to identify which reusable "skills" (packaged, reusable instruction sets a coding agent can invoke) each phase would need. It identified three skills to build from scratch — `speech-collector`, `youtube-transcript`, and `discourse-coder` — and two pre-existing general-purpose skills to reuse (`pdf` for Phase 1's PDF reading, `xlsx` for Phase 2's spreadsheet reading). It proposed draft `SKILL.md` outlines for each, in the recommended build order: `speech-collector` first (needed before Phase 2 could start), `youtube-transcript` alongside it, `discourse-coder` before Phase 3. All three were subsequently built, and `discourse-coder` in particular went through four major version rewrites over the life of the project (`discourse-coder`, `-v2`, `-v3`, `-v4`), described in full in Section 5 below.

## 1. Phase 1 — The Methodologist: building the first codebook

**Workflow file:** `workflows/1_methodologist.md`. **Goal:** understand the proposed methodology and produce the first version of `analysis/coding_book.md`.

The steps as written in the workflow file: navigate to `docs/methodology/` and `docs/references/`, read the PDFs there (using PDF-parsing tools), review the research abstract in `docs/abstract/`, read the (at that point nonexistent) `analysis/coding_book.md`, propose deductive categories aligned with an abductive approach, and write up findings in a methodology summary.

The source material available to this phase was: three methodology PDFs in `docs/methodology/` (`Diagrams _ Narratives -_ policy outputs.pdf` — a conceptual diagram mapping narratives to policy outputs; `discourse analysis.pdf`; `Week 9 Lecture Slides.pdf`), and five academic references in `docs/references/` on climate obstruction in Argentina and the Global South, including Christel, Gutiérrez & Möhle (2025) on obstruction perceptions in Argentina specifically, and a chapter on climate obstruction across the Global South. The abstract in `docs/abstract/` framed the overall research question (later formalized as: how does libertarian-populist governance in Argentina reshape sustainability policy and public scientific capacity through narrative delegitimization and material capability erosion).

**Output: `analysis/coding_book.md` (v1), dated April 2026 per `analysis/methodology_summary.md`.** This first codebook organized Milei's rhetoric into four "pillars," extracted directly from the conceptual diagram PDF:

1. **Epistemological Discrediting** — four sub-codes: `Knowledge_Problem` (no planner can aggregate the knowledge needed for climate action), `No_Market_Failures` (externalities reframed as state failure, not market failure), `Fallacy_of_Authority` (challenging scientific consensus as such), `Government_Failure` (the "intervention spiral" argument).
2. **Denialism** — two sub-codes: `Natural_Cycles` (climate change as a historical natural cycle, not anthropogenic) and `Manipulated_Models` (claims that climate models are unreliable, "oversaturated" with parameters).
3. **Cultural Backlash** — three sub-codes: `Woke_Bundling` (merging climate and gender into one progressive enemy), `Neo-Marxism` (green agenda as disguised socialism), `Sovereignty_Threat` (the 2030 Agenda as world government).
4. **Dual Policy Output** — a structural tracker, not a rhetorical code, meant to flag when the above three pillars translate into either "Discursive Delegitimation" or "State Capability Erosion." This fourth pillar is the earliest version of what would later become the project's two-dimension architecture (Section 5.2 below).

The `methodology_summary.md` accompanying this codebook states explicitly that Phase 1 was complete and the project was "ready to transition to Phase 2," with the Narrative Analyst agent expected to have "the freedom to detect novel patterns... and add them as emergent inductive categories" — i.e., the abductive design (deductive seed categories + inductive expansion) was baked in from the very first version, not added later.

## 2. Phase 2 — The Data Collector: building the corpus

**Workflow file:** `workflows/2_data_collector.md`. **Goal:** populate `data/raw_speeches/` with the full text of Milei's speeches and discourses.

### 2.1 Initial seed and supplementary search

The starting point was `data/sources/Notes.xlsx`, an existing spreadsheet of candidate URLs (the "preliminary html sources," per the workflow file). The workflow instructed the agent to use this as a starting point, then conduct "extensive web search to include more discourses, interviews, and references" beyond the seed list, and to extract transcripts from any YouTube links found.

A supplementary search pass on **2026-06-17** produced `data/sources/candidate_sources_log.md`, an 11-item pool of additional speeches/interviews not yet in the collection log, sorted by formality and annotated with a climate-relevance judgment: the G20 Leaders' Summit (Rio, 2024-11-18, high relevance — rejected Agenda 2030 climate language in the communiqué); a Le Point interview (2025-02-05, flagged "very high" priority — Milei reportedly called the Paris Agreement "a fraud" and denied human causation); the Knesset speech (flagged *low* priority, to be verified before collecting, since its focus is antisemitism/embassy relations rather than climate); CPAC Washington 2024, CPAC Argentina, the CPAC gala at Mar-a-Lago, the Vox "Europa Viva 24" rally in Madrid, the Hayek Medal acceptance, a Hispanic Prosperity Gala, the Lex Fridman podcast, and the 2025 midterm-election victory speech (flagged low priority — general political content). This file explicitly instructed that items should be "updated or removed/promoted into `collection_log.md` as Phase 2 proceeds" — i.e., it was a working queue, not a permanent record.

### 2.2 Building the master corpus index

At some point after the initial ad hoc collection, the project shifted to a more systematic approach: scraping the entirety of Casa Rosada's official "Discursos" registry to build an exhaustive index of every recorded Milei speech as President, rather than relying on manually curated candidate lists. This produced `data/sources/milei_discursos_index_2023-2026.md` / `.csv` — 192 entries spanning December 2023 to April 2026, each with date, location, event type, a climate-relevance heuristic (`✔` high / `~` possible / blank unlikely), and a source link. The collection log records the moment this became the new master worklist: "2026-07-04 batch: began collecting from the new master index... 192 speeches, Dec 2023–Apr 2026. Started with climate-flagged (✔) items."

This index was later superseded by `data/sources/milei_discursos_index_2023-2026_updated260718.csv.csv` (18 July 2026), the current authoritative master corpus database, which reorganizes the same underlying data with a stable `id` column and a `coded` tracking column (see Section 6). It contains 193 rows, not 192 — the discrepancy is not an error: row `id=1` is the 8 October 2023 second presidential debate, delivered *before* Milei's 10 December 2023 inauguration and therefore outside the "Dec 2023–Apr 2026" window the earlier index's own description used loosely; it was included from the start (it appears as the very first row) because it was already part of the six-speech benchmark set used to build codebooks v1–v3 (Section 5).

### 2.3 Collection method and practical constraints

The `speech-collector` skill (built per the `SKILLS_ANALYSIS.md` plan) formalized the extraction process: fetch each page, strip boilerplate (navigation, cookie banners, share buttons, "related articles"), keep everything attributed to Milei plus interviewer questions and stage-direction-style context ("applause," "shouting from the crowd"), save with a standard YAML frontmatter (`title`, `date`, `source_url`, `source_type`, `language`, `youtube_transcript`, `summary_en`), name the file `YYYY-MM-DD-slug.md`, and log the result in `data/raw_speeches/collection_log.md`. Casa Rosada's specific page structure was reverse-engineered and documented in the skill: the speech body sits between the bold H2 title line and the `× Suscribite con tu mail` footer block.

In practice, collection ran into real constraints that the collection log documents candidly:

- **Length limits.** Many Casa Rosada pages exceeded the web-fetch tool's length limit. For these, the collector saved a condensed version — the opening and closing of the speech plus a `NOTA DEL RECOLECTOR` (collector's note) summarizing the body, with any climate-relevant passage preserved verbatim regardless of where it fell in the speech. Dozens of files in the July 2026 collection log carry the annotation `OK (condensado; excedió límite de fetch)`.
- **Source blocking.** The World Economic Forum's own Spanish-language site (es.weforum.org) returned HTTP 403 for the Davos 2024 speech, so the official Casa Rosada transcript was used instead. `americanrhetoric.com` also returned 403 and was not used even as a fallback (its content would have been an English translation, not the Spanish original, and the project's policy — see Section 2.4 — was to prefer the primary-language transcript).
- **Best-available-source substitution.** The UN 79th General Assembly address (2024-09-24) had no clean official Spanish transcript readily extractable, so it was collected from a Council on Foreign Relations article by Elliott Abrams that had appended the full English-translation speech text. The UN 80th address (2025-09-24) *did* have a clean official Spanish Casa Rosada transcript and was collected from there directly. This is why the corpus contains a small number of English-language speech files for otherwise Spanish-dominant events, and it is why a duplicate-transcript problem later emerged (Section 6.4, Section 7.2).
- **A secondary-source item retained for provenance.** `2023-10-22-milei-debate-presidencial-clima.md` is a Chequeado (fact-checking outlet) article about the same 2023 debate; it was superseded by the primary YouTube-transcript version of the debate itself but kept in the corpus folder for reference, not counted as an independent speech.

### 2.4 Full-text remediation pass (July 2026)

The condensation practice above was later judged insufficient for the project's needs, and a dedicated remediation pass was run. Two "Actualización" (update) entries appended to `collection_log.md`, both dated **2026-07-06**, record this:

1. First update: "Corpus: 134 discursos en `data/raw_speeches/`, todos con transcripción verbatim completa (0 condensados)." The 74 files that had been saved as condensed extracts with a collector's note were re-fetched and replaced with the full Casa Rosada text, frontmatter preserved, no boilerplate.
2. Second update: "corpus completo (192/192)" — the remaining 62 speeches missing from the raw corpus (August 2025 – April 2026, plus three earlier items: the Llao Llao forum, the UN 2024 address, and the Davos 2025 address) were collected, bringing the total to 196 `.md` files in `data/raw_speeches/` (the count exceeds 192/193 because a small number of duplicate-language and superseded-secondary-source files are retained alongside the primary file for each event), all with full verbatim transcription, zero missing against the master index.

This is the state `data/raw_speeches/` has been in since 6 July 2026: a complete, verbatim, boilerplate-free corpus of every indexed Milei speech, in its original language, ready for coding.

### 2.5 Skills built in this phase

- **`speech-collector`** (`skills/speech-collector/SKILL.md`) — HTML scraping, boilerplate stripping, frontmatter/naming conventions, collection logging, as described above.
- **`youtube-transcript`** (`skills/youtube-transcript/SKILL.md`) — a three-tier extraction approach: (1) `yt-dlp --write-auto-subs --sub-lang es --skip-download` to pull the VTT/SRT caption file directly, with Portuguese/English as language fallbacks; (2) browser-based manual transcript extraction if `yt-dlp` fails; (3) if no captions exist at all, set `youtube_transcript: false` and summarize from title/description only, logging status `NO_TRANSCRIPT`. The skill explicitly instructs *not* to "fix" the Spanish transcript — false starts, repetitions, and colloquialisms are preserved because they are analytically meaningful, and code-switching (Spanish/English mixing) is flagged with `language: es-en` rather than normalized away.

## 3. Phase 3 — The Narrative Analyst: four codebook iterations before scaling

This is the longest and most iterated phase of the project. Before the coding framework was ever applied to the full 193-speech corpus, it went through four complete versions (v1 → v4), each one applied to a small, fixed **benchmark set** of flagship speeches so the researchers could evaluate and refine the categories cheaply before committing to full-corpus coding. Understanding this benchmark-then-scale structure is essential to reading the rest of this document: **v1, v2, and v3 were never applied to more than 9 speeches. Only v4 was scaled to the full corpus**, and only after two more rounds of methodological correction (Section 6).

### 3.1 v1 pass — the four-pillar codebook on six flagship speeches

The v1 codebook (Section 1 above) was applied to six speeches, chosen for their evident climate/sustainability content and prominence: the 2023 presidential debate, the Davos 2024 address, the UN General Assembly 2024 address, the Davos 2025 address, the UN 80th General Assembly 2025 address, and the Davos 2026 address. These six coded files live in `analysis/coded_speeches/v1/`, alongside an early spreadsheet artifact, `milei_coded_excerpts_v0.xlsx`.

The `discourse-coder` (v1) skill defined the annotation format used for the rest of the project's life, with only incremental changes in later versions: work paragraph by paragraph; after any paragraph with codeable content, add an inline annotation of the form `` `[CODE: Pillar > Sub-code]` — *Memo: 2–4 sentence justification* `` immediately below it; stack multiple codes vertically if a passage genuinely earns more than one; leave uncoded paragraphs untouched; write memos in English regardless of the speech's source language; maintain a running frequency-count JSON; append a structured "Coding Summary" to the end of each coded file (dominant codes, new inductive categories, notable rhetorical moves, flagged uncertainties). Note that the v1 skill specified output to `data/processed/coded/` and the tally to `data/processed/frequency_tally.json` — a location that was later abandoned; `CLAUDE.md` now explicitly states `data/processed/` is "NOT USED" and all coded output lives under `analysis/coded_speeches/`. This relocation happened sometime between v1 and v2/v3 (both of which already output to `analysis/coded_speeches/v#/`) and is not separately documented, but it is a real structural correction worth knowing if old references to `data/processed/` are encountered.

The v1 pass produced **four inductive categories**, each documented in `coding_book.md` with a formal definition, a worked example, and the file it was first identified in:

- **`Civilizational_Defense_Frame`** — first identified in the Davos 2024 speech. A master frame positioning Western civilization as under existential threat from socialism, making every specific policy critique (including climate) a front in a civilizational war.
- **`Selective_Empiricism`** — first identified in Davos 2024, flagged as "tentative; flag for recurrence... before applying routinely." The pattern of claiming empirical authority for pro-market claims while dismissing opposing (including climate) knowledge as ideologically captured.
- **`Temporal_Appropriation`** — first identified in the UN 80th Assembly speech (2025-09-24). Co-opting the intergenerational-responsibility language of sustainability discourse and redirecting it *against* sustainability governance.
- **`Reported_Denial`** — first identified in the 2023 presidential debate: an opponent's (Bregman's) reported-speech paraphrase of a Milei climate position, coded as corroborating context rather than primary discourse, and flagged from the outset as "tentative — 1 corpus instance."

All four of these categories had long, consequential afterlives in the project — three were carried forward through v2 and v3 as candidate codes, and their ultimate fates (promoted, eliminated, retired) are recorded in Section 5.4.

### 3.2 v2 — reframing around a dual mechanism

**`analysis/coding_book_v2.md` / `analysis/methodology_summary_v2.md`, dated June 2026.** This revision was motivated by a research-design document referenced as `docs/Draft/draft_literaturereview_researchdesign.md`, which is no longer present under that filename in the project (it appears to have been folded into what is now `docs/Draft/draft_20260718.md`, the first full paper draft). That research-design work integrated three literatures — climate obstruction/discourses of delay, policy dismantling theory, and right-wing populism/climate backlash — and this integration is what motivated restructuring the codebook.

`methodology_summary_v2.md` names three specific limitations of the v1 four-pillar structure that v2 was built to fix: (1) "Epistemological Discrediting" and "Denialism" both targeted epistemic authority at different levels but were treated as parallel, equal-weight pillars, obscuring their different mechanisms; (2) the "Dual Policy Output" tracker treated institutional change as a residual afterthought of rhetoric rather than a mechanism in its own right, when the policy-dismantling literature (Bauer et al. 2012) treats capability erosion as co-constitutive, not derivative; (3) v1 was purely speech-focused, with no room to code passages that reference institutional or budgetary change.

v2 replaced the four pillars with a **two-dimension architecture** that, in slightly revised form, is what the project still uses today:

- **Dimension 1 — Discursive Delegitimization**, with three sub-dimensions: **D1.1** (state intervention & sustainability governance), **D1.2** (public science & expertise), **D1.3** (woke/cultural backlash).
- **Dimension 2 — State Capability Erosion**, with three sub-dimensions: **D2.1** (budgetary retrenchment), **D2.2** (institutional downgrading & administrative restructuring), **D2.3** (sustainability-policy dismantling).

The same six benchmark speeches were recoded from scratch under v2 (not incrementally patched — the skill instructs basing v2 annotations "on the raw text, not on v1 decisions"), saved to `analysis/coded_speeches/v2/`, with a new `frequency_tally_v2.json`. The `discourse-coder-v2` skill required a "Comparison to v1 coding" field in each speech's summary, specifically to build "the iterative argument about what the new framework adds analytically" — i.e., version-over-version comparison was a designed-in feature of the process, not an afterthought.

**The problem v2 introduced (discovered during/after this pass):** because D1 and D2 were both being coded from the *same* speech corpus, several passages where Milei referenced an institutional action in a speech — e.g., "Argentina decided to exit the 2030 Agenda process," or a call to reduce supranational organizations — were coded as D2 (`D2.3 > Withdrawal_from_International_Initiatives`, `D2.2 > Agency_Elimination_or_Merger`). This is the problem v3 was built to fix.

### 3.3 v3 — separating the two corpora

**`analysis/coding_book_v3.md` / `analysis/methodology_summary_v3.md`, dated June 2026.** `methodology_summary_v3.md` states the problem plainly: conflating D1 and D2 within the speech corpus "blurs the mechanism" the article's core argument depends on (rhetoric delegitimizes; formal action dismantles — if one data source is asked to provide evidence for both halves of that claim, the dual-mechanism argument becomes assertion rather than demonstrated fact), "misrepresents the nature of speech data" (speeches are performances/announcements, not the institutional acts themselves), and "understates the rhetorical richness of D1" (a passage announcing a multilateral exit is doing real discursive work — framing it as principled, sovereignty-defending, etc. — that a D2 code discards).

The fix: strict data-source separation. **Corpus A** (presidential speeches — the corpus that had existed all along) is coded with **Dimension 1 only**. **Corpus B** (formal governmental documentation: executive decrees, budget records, administrative reorganization documents) is coded with **Dimension 2 only**, and — as of this writing, still — has not yet been collected (see Section 9). Passages that had been coded D2 in v2 because they referenced an institutional announcement were re-mapped to the appropriate D1 sub-code — typically `D1.1 > Rejection_of_Multilateral_Governance` for exits/withdrawals, `D1.1 > Anti_State_Anti_Bureaucratic` or `D1.1 > Delegitimization_of_Regulation` for restructuring justifications.

This pass also **expanded the benchmark set from 6 to 9 speeches**, adding the three "Apertura de Sesiones Ordinarias" (State of the Nation) addresses: 142° (1 March 2024), 143° (1 March 2025), and 144° (1 March 2026). The nine coded files live in `analysis/coded_speeches/v3/`, with `frequency_tally_v3.json` recording **`corpus_size: 9`** and the note: "Apertura sessions (142, 143, 144) added in second coding pass on 2026-06-08." Three inductive categories were carried forward as candidates from v1/v2: `Selective_Empiricism`, `Temporal_Appropriation`, `Reported_Denial`.

**Output generation was formalized in this pass.** The `qda-outputs` skill (`skills/qda-outputs/SKILL.md`) was built at this point to standardize what had previously been an ad hoc reporting process: two deterministic Python scripts (`generate_xlsx.py`, `generate_html.py`) produce the Excel workbook and the interactive HTML corpus explorer directly from the coded `.md` files, and a written analytical report (`final_analysis_report_v3.md`) is composed by the analyst following a fixed template with "Analytical Anchors" — pre-computed observations about the v3 corpus that the report-writer should verify against the live tally rather than take on faith.

`analysis/results/v3/final_analysis_report_v3.md` (8 June 2026) reports: 9 speeches, 8 October 2023 – 1 March 2026, **98 total code annotations** across 85 coded passages. Dimension split as stated in that report: D1.1 = 57 (58.2%), D1.2 = 14 (14.3%), D1.3 = 21 (21.4%), Inductive = 6 (6.1%). It is worth recording a small internal inconsistency here for the historical record: `frequency_tally_v3.json`'s own `_corpus_notes` block, computed by summing its sub-code counts directly, gives slightly different numbers (D1.2 = 15, D1.3 = 24, inductive total = 8, for a grand total of 104 rather than 98) — a minor hand-maintained-tally drift of exactly the kind that motivated building an automated, single-source-of-truth parser in v4 (Section 6.2). The headline finding of the v3 report — that D1.1 (governance delegitimization) dominates at roughly 58%, while direct climate-science denial (D1.2's `Climate_Skepticism_or_Dismissal`, n=2) is rare — proved durable and is the same core finding the v4 full-corpus pass later confirmed at much larger scale (Section 6, Section 8).

The v3 report also identified `Temporal_Appropriation` (n=3 across the 9-speech corpus: UN 80th 2025 ×2, Apertura 2026 ×1) as "the strongest candidate for formalization as a permanent deductive code," exceeding what the report calls "the informal threshold" of two or more corroborated instances. This recommendation was revisited — and reversed — during the v4 peer review (Section 3.4).

### 3.4 v4 — peer review of the benchmark corpus and codebook consolidation

This is the version currently in force. It began not as an agent-driven redesign but as a **human peer-review pass**: Germán and Juani (Juan) independently reviewed the full v3-coded 9-speech benchmark corpus, working from a "Coded Passages" sheet and an "Analysis of Categories" sheet in a review workbook, `qda_v3_coded_corpus_v3_feedback.xlsx`. Their line-by-line and category-level comments were captured verbatim in `analysis/coding_book_v4_proposal.md` (a "change proposal, not the final codebook," per its own header) before being finalized into `analysis/coding_book_v4.md`.

**The single most consistent cross-cutting signal from both reviewers was overcoding** — too many codes stacked on one passage. The proposal document quotes specific reviewer comments against specific passage IDs: IDs #14+15 (`Market_Primacy` + `Delegitimization_of_Regulation` on the same passage — Germán: *"podría unificarse"*), IDs #22+23 (two `Delegitimization_of_Regulation` codes on adjacent sentences — *"podría unificarse"*), IDs #42+43 and #48+49 (`Woke_Bundling` + `Neo_Marxism` stacked — Juani: *"no, overcoding"* / *"not sure, overcoding"*), ID #27 (`Civilizational_Defense` stacked on an already-D1.1-coded passage — Juani: *"atención al overcoding"*). This produced the **overcoding rule** that has governed all coding since: apply one primary code per passage; stack a second only if it captures a genuinely distinct rhetorical move; the test is whether removing the second code would still leave the passage's core analytical insight intact.

The full set of substantive changes finalized in `coding_book_v4.md` (dated July 2026, with worked examples explicitly added on **2026-07-19**):

| Change | What happened | Why |
|---|---|---|
| Merge | `Deregulation_Benefits` → absorbed into `Delegitimization_of_Regulation` | Reviewers identified these as two faces (negative/positive) of the same argument; keeping them separate created artificial frequency splits |
| Merge | `Attack_on_Universities` + `Attack_on_Public_Research_Institutions` → `Attack_on_Universities_and_Research_Institutions` | Both activated by the same rhetorical mechanism (institutional capture) and applied interchangeably in practice |
| Merge | `Rejection_of_Expert_Mediation` → absorbed into `Attack_on_Experts_and_Technocrats` | The institutional-role critique and the personal/class delegitimization are analytically unified in practice — Milei always moves from one to the other in the same passage |
| Rename | `Neo_Marxism` → `Anti_Socialism_Anti_Collectivism` | Both reviewers reached for "anti-socialism"/"anti-collectivism" language when discussing D1.3 passages; the new label captures the rhetorical *function* rather than mirroring Milei's own polemical vocabulary, and is broader (captures collectivism framings that don't explicitly invoke Marxism) |
| Promotion | `Selective_Empiricism` (inductive since v1) → formal deductive D1.2 sub-code | Both reviewers independently proposed this; the pattern (appropriating empirical authority for pro-market claims while denying it to climate science) was judged consistent and distinctive enough to be permanent |
| Restoration | `Sustainability_as_Ideological_or_Harmful` — the v4 proposal initially recommended retiring it as redundant, but it was restored after review | It captures a distinct register (the policy *response* framed as harmful) not fully covered by adjacent codes |
| Broadening | `Rejection_of_Multilateral_Governance` scope widened beyond environmental governance specifically | Reviewer comment: "consider a broad definition... not only environmental" — Milei's rejection of multilateral governance operates at a sovereignty/self-determination level that subsumes but isn't limited to climate bodies |
| Elimination | `Temporal_Appropriation` — all three v3 instances individually rejected by peer review (#61: *"I will change it to D1.1 or D1.2"*; #66: *"NO. Eliminar."*; #97: *"NO. ELIMINAR."*) | The v3 application threshold was too low — passages that merely invoked the future or generational language, without specifically co-opting sustainability's own vocabulary, had been miscoded. Retained on a "watchlist" with a stricter two-condition test in case it re-emerges unambiguously |
| Retirement | `Reported_Denial` | Reviewer: *"N/A — no es dicho por él mismo... es más bien una referencia de dichos previos."* The unit of analysis is Milei's own primary discourse; a third party's paraphrase of his position is out of scope |
| New rule | Overcoding rule formalized (see above) | Cross-cutting reviewer signal, described above |

Applying this recoding manifest to the v3 corpus's 98 annotations produced an estimated v4 baseline of roughly 88–90 annotations (10 removals for retired/rejected categories, 0–2 pending additions the reviewers flagged as candidates but did not finalize). Each of the fourteen surviving deductive sub-codes was then given **three worked examples** in the codebook — real coded passages (or, where the small benchmark corpus didn't yet contain three genuine instances, clearly labeled illustrative constructions) — specifically so that when coding scaled up from 9 speeches to the full corpus, whoever (or whatever) was doing that coding would have concrete calibration points rather than abstract definitions alone.

The `discourse-coder-v4` skill (`skills/discourse-coder-v4/SKILL.md`) encodes all of the above as explicit rules: Rule 1 (D1 only for speeches, carried over from v3), Rule 2 (the overcoding rule, new in v4), Rule 2b (added slightly later — see Section 6.3), Rule 3 (retired-category list), and — added even later still, on 2026-08-06 — Rule 4 (verbatim text preservation, see Section 7.1).

## 4. The pivot: from a 9-speech benchmark to the full 193-speech corpus

Every version described above (v1–v4) had been applied only to the small, hand-picked benchmark set. `analysis/methodology_summary_v4.md` records the decision to change this: "The v4 codebook and skill are applied going forward to the **full corpus of Milei speeches and discourses as President**, not only the pre-selected climate-flagged subset used to build v1–v3." At the moment this decision was recorded, 9 speeches had already been coded under v4 (the recoded benchmark set) and "the remaining ~184 are outstanding."

This is a significant methodological escalation, not a mechanical continuation: the benchmark set had been curated for high climate salience (Davos, UN, Apertura), so a codebook that behaved well on that set had never been tested against the much larger population of routine, non-obviously-climate-related speeches (ribbon-cuttings, bilateral meetings, award ceremonies, military ceremonies) that make up most of the actual corpus. As Section 6.3 documents, this exposed a real scope ambiguity in the codebook that the benchmark set had never surfaced.

## 5. Scaling to the full corpus: the batch process

**Workflow file:** `workflows/3_narrative_analyst.md` (v4 version). The process specified: read the v4 skill and codebook in full before touching any file; confirm no higher codebook version exists; select the next batch of five uncoded speeches from the master corpus database, prioritizing rows flagged `clima = ✔` then `clima = ~` (blank-flagged rows lowest priority, explicitly allowed to be skipped or deferred with the decision flagged rather than silently coded through); code the batch with `discourse-coder-v4`, saving each file to `analysis/coded_speeches/v4/<same filename>.md`; regenerate the frequency tally from the coded files (not hand-edit it); mark the corresponding master-CSV rows `coded = ok`; repeat until the corpus is exhausted; then hand off to `qda-outputs` for the three deliverables.

Matching a master-CSV row to its raw-speech file required care, since the CSV carries no filename column: matching was done by date plus event keywords, or by cross-referencing `data/raw_speeches/collection_log.md` (URL → filename), with the note that the CSV's `fecha` (the Casa Rosada listing date) can be off by a day from the raw file's own frontmatter `date`, in which case the event description is the tiebreaker.

### 5.1 The automated frequency-tally parser

A structural fix was introduced at this stage that materially improved data reliability for the rest of the project: `skills/qda-outputs/scripts/corpus_data.py`, a single canonical parser. Before this script existed, `generate_xlsx.py` and `generate_html.py` each had their own independent regex-based parser for the `[CODE: ...]` annotation format, and `frequency_tally_v#.json` files were hand-maintained — both of which are exactly the kind of setup that produced the v3 tally/report discrepancy noted in Section 3.3. `corpus_data.py`'s docstring names this problem directly ("Silent code-name drift... A typo'd sub-code, or a retired v3 code applied by habit... used to be ingested silently and counted under its own bucket") and fixes it with a single `validate_code()` function that flags any code not in the current v4 schema (retired or typo'd) as a warning, and a single `build_corpus()` / `parse_speech_segments()` pipeline that both the Excel generator, the HTML generator, and `update_frequency_tally.py` all now call — so the three outputs can never silently diverge from each other, and the tally can never drift from what the coded files actually contain. `update_frequency_tally.py` prints a diff against the previously saved tally every time it runs; a nonzero diff after a coding batch is expected, but a nonzero diff when no coding happened means something is wrong and needs investigating before proceeding.

### 5.2 Batch 2 and the scope crisis

The first batch drawn from the full, non-pre-filtered corpus (five speeches from December 2023 – January 2024) came back nearly empty — four of the five yielded almost no codes. This was flagged by the user specifically regarding `2023-12-20-milei-cadena-nacional-dnu-desregulacion.md`, a speech containing an extended anti-collectivist doctrinal passage ("un burócrata sentado [planificando] la vida de millones," "el Estado... se ha vuelto una máquina de impedir el comercio") that mapped directly onto the codebook's own "recognize by" language for `Anti_Casta`, `Anti_State_Anti_Bureaucratic`, and `Anti_Socialism_Anti_Collectivism`, yet had received only a single code in the whole speech.

The diagnosis, recorded in `analysis/_draft_v4_batch2_consistency_audit.md`, is that the codebook contained **two contradictory practices side by side, and different coding passes had unknowingly reached for different ones.** The 9-speech benchmark set (all pre-filtered for high climate relevance) had, in practice, coded generic anti-state/anti-casta/anti-regulation passages *even when they contained no climate content at all* — e.g., "la casta política es lo peor que le puede pasar a un país como el nuestro" (Apertura 2024) was coded `Anti_Casta` with a memo explicitly framing it as foundational infrastructure "later applied to environmental agencies, sustainability technocrats." But `CLAUDE.md`'s constraints section at the time additionally stated "do not code general economic or political speeches unless they contain relevant climate-adjacent rhetoric" — a stricter, passage-level filter the benchmark set had never actually been forced to apply consistently (because climate content was usually present *somewhere* in those speeches, generic passages could ride along inside an otherwise climate-heavy speech without ever testing the boundary). Batch 2's speeches were genuinely low-climate-content, general-economy addresses, so the coder defaulted to the stricter written rule — and did so consistently across all five, which is why four came back essentially empty.

The audit's own framing is important for the historical record: "This isn't simply 'the new coder got sloppy'... the ambiguity predates Batch 2; it was latent in the benchmark corpus itself, just never triggered at scale because the original 9 were all pre-filtered as high-climate-relevance speeches." The audit laid out two explicit, mutually exclusive options rather than silently picking one: **Option A** (adopt the benchmark's permissive standard going forward — generic anti-casta/anti-state/deregulation/collectivism rhetoric is codeable wherever it appears, on the theoretical grounds already stated in the codebook's own D1.1 introduction) or **Option B** (formalize Batch 2's stricter standard and retroactively prune the benchmark corpus's non-explicit passages for consistency).

### 5.3 Resolution: Option A, and the codebook's scope rule

**Option A was adopted** on 2026-07-19. This is documented in three places that should all agree (and do): `CLAUDE.md`'s "Important Constraints" section, `coding_book_v4.md`'s "Instructions for the Analyst Agent" (added as rule 2b), and `skills/discourse-coder-v4/SKILL.md`'s "Rule 2b." The final rule: the master database's `clima` column is a *speech-selection* heuristic only — it decides which speeches get coded first, not whether a given passage inside a selected speech gets coded. Once a speech is selected for coding, general `Anti_Casta`, `Anti_State_Anti_Bureaucratic`, `Delegitimization_of_Regulation`, `Market_Primacy`, `Attack_on_Experts_and_Technocrats`, `Attack_on_Universities_and_Research_Institutions`, and `Anti_Socialism_Anti_Collectivism` rhetoric is coded wherever it appears, without requiring the passage itself to mention climate, the environment, or the 2030 Agenda — because, per the codebook's own theoretical framing (carried since v1), this rhetoric constitutes the discursive infrastructure that climate-specific attacks later plug into, "regardless of whether formal commitments remain in place."

A worked boundary example was added alongside the rule to prevent it from being misread as "code everything": a speech with genuinely *no* anti-state/anti-casta/anti-regulation/anti-collectivist/anti-expert/civilizational content — purely ceremonial, biographical, or diplomatic material such as condolences or bilateral pleasantries — still receives zero codes, because there is no delegitimization move of any kind to find, not because the move present lacks a climate label. The codebook cites `2024-01-26-milei-dia-holocausto-museo.md` (a Holocaust Remembrance Day address) as the canonical example of a correctly zero-coded speech under this rule.

Once this rule was fixed, Batch 2's five originally under-coded speeches were presumably recoded under the corrected standard (the audit does not itself contain a follow-up confirmation, but the rule was in force for all subsequent batches).

### 5.4 Completing the full-corpus pass

Coding continued in batches of five, chronological (oldest first), through the remainder of the 193-speech corpus, prioritizing `clima = ✔` then `~` then blank rows as specified in the workflow. The frequency tally was regenerated after each batch (or every 3–5 files) via `update_frequency_tally.py`, and the corresponding master-CSV rows were marked `coded = ok` as the running, shared progress record.

**By 2026-07-19, all 193 speech events were coded** (196 physical files in `analysis/coded_speeches/v4/`, including three non-authoritative English-language duplicate transcripts of already-coded events — see Section 6.4 below), and all 193 master-CSV rows read `coded = ok`. The three `qda-outputs` deliverables were generated for the first time from the complete corpus: `qda_v4_coded_corpus.xlsx`, `qda_explorer_v4.html`, and `final_analysis_report_v4.md`, plus a supplementary per-speech quantitative CSV, `milei_corpus_v4_code_counts.csv` (the master corpus database with one added column per sub-code, for statistical analysis outside the qualitative-coding tooling). A latent bug in `generate_xlsx.py` — a single-letter Excel-column-naming assumption that broke once the corpus exceeded 24 speeches — was discovered and fixed during this pass (switched to `column_index_from_string`).

### 5.5 The Davos duplicate-transcript double-counting bug (discovered while writing the first full-corpus report)

While writing `final_analysis_report_v4.md`, a verification check found that two pairs of duplicate-language files (the Spanish-original and English-host-transcript versions of the same underlying Davos 2025 and Davos 2026 speeches) had **both** retained live, machine-parseable `[CODE: ...]` tags, despite explanatory notes in the files stating only one version of each pair should count — silently double-counting 26 code instances in the frequency tally. This was corrected by de-formatting the stray tags in the non-counted duplicate to plain, non-parseable text (preserved for provenance, no longer parsed by `corpus_data.py`), and regenerating the tally, Excel workbook, and HTML explorer. All statistics in `final_analysis_report_v4.md` (dated 2026-07-19) reflect the corrected corpus.

## 6. Quality-control episodes after the corpus was "complete"

The corpus being marked complete on 2026-07-19 did not mean the coded text itself was necessarily correct or complete — two further, independent problems were subsequently discovered and are documented here in full because they materially affect how any statistic drawn from the corpus before their fixes should be interpreted.

### 6.1 The excerpt-omission bug (discovered 2026-08-06)

**Trigger:** Juan, reviewing the HTML explorer, noticed content appeared to be missing from some coded files and flagged three specific examples.

**Diagnosis**, recorded in full in `analysis/_draft_v4_excerpt_omission_audit.md`: the problem was far larger than the three flagged files. **150 of 197 files (76%) in `analysis/coded_speeches/v4/`** had had their uncoded passages replaced with bracketed editorial summaries — e.g. `[... left uncoded in its entirety: moral-hierarchy framework, Kirzner citation, Hoppe property-rights proof ...]` — instead of the actual paragraph text, in direct violation of the skill's own explicit instruction that "paragraphs with no codeable content pass through unchanged." Quantified: across the 150 affected files, the raw source speeches totaled 575,309 words; the corresponding coded files totaled only 117,664 words — despite coded files normally being *longer* than their source (they add code tags and memos on top of the full text). Some "kept" paragraphs were also internally truncated mid-sentence with `[...]` ellipses, independent of the larger omitted blocks — this affected the Excel workbook's Coded Passages sheet directly, since it pulls the coded-passage text verbatim: 97 of 197 files had truncated passage text there.

**Root cause:** no rule anywhere (skill, codebook, or `CLAUDE.md`) sanctioned summarizing or omitting text; this was an undocumented shortcut some coding passes took on long, highly repetitive speeches (Milei's 2025–2026 Davos/CPAC/forum circuit reuses the same set-piece arguments — Hoppe's proof, the Pharaoh allegory, "el fallo de mercado es un oxímoron" — nearly verbatim across many venues), evidently reasoning that the "Overcoding decisions" summary field's legitimate purpose (explaining why a *second code* wasn't stacked on an already-fully-present passage) licensed deleting the passage's text outright on grounds of near-duplication. All 150 affected files carried the same `coded_date: 2026-07-19`, but so did 42 of the 47 unaffected files — this was not one bad session cordoned off by date, but a failure mode that recurred across the full-corpus pass whenever a speech happened to strike the coder as highly repetitive.

**A second, independent problem** was found in the same audit, in one file: `2025-07-22-milei-la-derecha-fest-cordoba.md` did not just omit text but **reordered passages out of the sequence they appear in the raw transcript**, collating non-adjacent sentences from different parts of the speech into single "paragraphs" for thematic presentation — a distinct methodological deviation from the chronological pass-through the skill requires.

**Remediation, in two dated passes:**

*First pass, 2026-08-06.* Because the codes and memos themselves were judged analytically sound on inspection (a formatting/completeness failure, not a coding-quality failure), the fix was designed as a **merge, not a re-code**: an automated script matched each affected file's existing `[CODE: ...]`/memo blocks back against the untouched, complete `data/raw_speeches/` source, snapped them to full raw-paragraph boundaries, and reconstructed the file as the full raw text with each code block re-inserted at the correct location. Every promoted file passed three automated checks (identical set of code tags before/after; reconstructed word count consistent with the raw source; no duplicated paragraphs) plus a manual side-by-side read of roughly 10 of the reconstructed files against the raw source. **85 of 150 files were fixed and promoted** in this first pass; `update_frequency_tally.py` reported zero count changes, confirming the merge restored text without altering the analytical corpus. A separate check on the xlsx's truncated-passage problem found it only partially resolved by the text-merge (truncation inside a coded passage itself is a different code path from omission of surrounding uncoded text): 97 files/219 rows affected before this pass, reduced to 51 files still affected after.

*Second pass, 2026-08-06 (same day, after Juan reported still seeing truncated files).* Two further matcher improvements: (1) a fuzzy-matching fallback for cases where the coded file's anchor text had small wording/punctuation drift from the raw source, combined with the original exact matcher (kept for short/formulaic lines the fuzzy scorer under-matches) — this alone fixed another 44 files; (2) while re-examining `la-derecha-fest-cordoba`, a second, more serious bug was found in the matcher itself: it had been collapsing a multi-fragment anchor (one code's anchor quoting two non-adjacent sentences joined by `[...]`) into a single min-to-max paragraph span, silently swallowing everything in between — including the true home paragraphs of four *other* codes later in the file, which ended up attached to the wrong passage. Critically, **this file had already been promoted in the first pass with this bug present** — codes preserved, but four of eight attached to the wrong location. This triggered an audit of all 119 files promoted up to that point for the same signature (a matched anchor spanning more than 4 paragraphs); 5 were affected (only `la-derecha-fest-cordoba` had a *later* code actually land in the wrong place; the other 4 just had oversized-but-correct chunks). The matcher was fixed to treat each `[...]`-separated fragment as an independent match, and all 5 affected files were regenerated, re-verified, and re-promoted.

**Result of the two passes: 132 of the original 150 affected files are fully restored** (full verbatim text, codes preserved and correctly placed, zero drift in the frequency tally reconfirmed after every batch). The Excel workbook's truncated-passage count dropped from 97 files/219 rows to 16 files/63 rows.

**Still open, as of this writing:** the remaining hard tail could not be safely resolved by the automated matcher and needs human judgment. As independently re-verified while writing this document (`grep -lE '^\[\.\.\.' analysis/coded_speeches/v4/*.md`), **18 files still contain unresolved omission markers**: `2024-05-22-milei-libro-luna-park.md`, `2024-09-24-milei-debate-general-del-79-periodo-de-sesiones.md` (a special bilingual-cross-reference case — see also Section 6.4), `2024-10-09-milei-ceal.md`, `2024-10-15-milei-jornadas-monetarias-bancarias.md`, `2024-10-19-milei-tech-forum-argentina.md`, `2024-11-12-milei-gala-endeavor.md`, `2024-11-13-milei-cena-fundacion-faro.md`, `2024-12-05-milei-cpac-argentina.md`, `2024-12-06-milei-reconocimiento-marketing-uruguay.md`, `2024-12-10-milei-cadena-nacional-ano-de-gestion.md`, `2025-02-21-milei-bid-washington.md`, `2025-06-11-milei-kneset-israel.md`, `2025-06-25-milei-la-libertad-avanza-puerto-madero.md`, `2025-08-04-milei-voceros-de-la-libertad-fundacion-faro.md`, `2025-11-13-milei-12-congreso-de-economia-regional-del-club.md` (**note: this is the periglaciares/glacier-law speech, the single most important passage in the corpus for D1→D2 triangulation — its surrounding text should be reconstructed with priority**), `2025-12-03-milei-encuentro-de-lideres-de-el-cronista-en.md`, `2025-12-15-milei-cena-de-fin-de-ano-de-la.md`, and `2026-04-28-milei-participacion-del-presidente-javier-milei-del-debate.md`. Most of these are multi-speaker/Q&A-format transcripts (interviews, debates with speaker labels like `BULLRICH.-`) or passages paraphrased heavily enough in the coded file that even fuzzy matching cannot confidently relocate the anchor — the audit's own assessment is that these "need a person (or a slower, more careful pass) rather than a script." **This is an unresolved item for the next work session on this project**, not a closed one.

**Fix going forward:** **Rule 4** was added to `skills/discourse-coder-v4/SKILL.md` on 2026-08-06: uncoded and near-duplicate passages must always be reproduced in full verbatim, never summarized or truncated with brackets, and passages must remain in transcript order; observations about cross-speech duplication belong only in the Coding Summary's "Overcoding decisions" field as a note, never as grounds to cut text. The audit's own closing observation is worth preserving verbatim as a methodological lesson: *"the script reported success" isn't the same as "verified correct" — the code-signature/word-count/duplicate-paragraph checks caught most failure modes but missed a code landing next to the wrong paragraph.*

### 6.2 The recap-methodology audit (2026-08-08)

A second, independent under-coding problem — distinct from the text-omission bug above — was found and fixed on **2026-08-08**. Where Section 6.1's bug was about deleting or truncating *text*, this one was about wrongly declining to *apply a code* to a passage on the grounds that its argument repeated content already coded in an earlier speech. The v4 codebook and skill had always required each speech to be coded on its own terms regardless of cross-speech repetition (this is explicit in Rule 4, added just two days earlier), but ten speeches from the 2026-07-19 pass had not followed this — presumably coded during or shortly after the period when the excerpt-omission bug was also active, and sharing its underlying logic (treating repetition as license to under-process a speech).

The ten affected files, all recoded on 2026-08-08 under the unchanged v4 codebook (no codebook version bump was needed — this was a coding-practice correction, not a category-definition change): `2026-03-14-milei-madrid-economic-forum-2026-en-espana.md`, `2024-11-15-milei-cpac-inversores-mar-a-lago.md`, `2025-06-12-milei-clase-magistral-universidad-hebrea-jerusalen.md`, `2025-09-24-milei-recibir-el-premio-global-citizen-2025-del.md`, `2025-09-30-milei-presentacion-del-libro-cambia-la-musica-del.md`, `2025-10-02-milei-presentacion-de-las-reformas-tolerancia-cero-con.md`, `2025-12-18-milei-la-entrega-de-sables-y-medallas-en.md`, `2026-03-10-milei-gala-anual-j100-de-the-algemeiner-en.md`, `2026-04-20-milei-su-par-de-israel-isaac-herzog.md`, `2026-04-29-milei-cierre-de-la-expo-efi-2026-en.md`.

**Effect on the corpus:** total code instances rose from 538 to 613 (+75, +13.9%); zero-code speeches dropped from 33 to 23 (of 193); `frequency_tally_v4.json`'s `corpus_size` field became 194 (194 physical files with live code tags, though only 193 count toward the master-CSV-matched statistics — see Section 6.4). This is documented in the tally's own `_metadata.note` field. Notably — and this is a substantively important fact, not just a bookkeeping one — **none of the 75 newly added codes fell under the corpus's three explicit climate-signature sub-codes** (`Sustainability_as_Ideological_or_Harmful`, `Rejection_of_Multilateral_Governance`, `Climate_Skepticism_or_Dismissal`, which remained at exactly 55 total instances before and after); all of the correction's added density is in the generic anti-state/anti-casta/anti-regulation/cultural-backlash infrastructure — which is exactly what the "discursive infrastructure" thesis (Section 5.3) predicts should be under-detected if a coder lapses back into requiring an explicit climate anchor.

### 6.3 Report update (2026-08-09)

In the immediately preceding work on this project (same overall engagement as this document), the corpus's current state was independently re-verified by running the canonical `corpus_data.py` parser directly against the coded files (rather than trusting the cached `frequency_tally_v4.json` or any spreadsheet), confirming the 613-code, 194-file, 23-zero-code state described in Section 6.2, and producing `analysis/results/v4/final_analysis_report_v4_20260809.md` — a new report, explicitly not overwriting the original `final_analysis_report_v4.md` (2026-07-19), documenting exactly what changed and why. ### 6.4 The duplicate-transcript problem, resolved definitively

Because this recurs across multiple sections above, it is worth stating the current, verified state plainly in one place. Three events in the corpus have two coded-language transcripts each (a Spanish original and an internationally hosted English transcript): the two Davos duplicate pairs were resolved in Section 5.5 by de-formatting the non-counted duplicate's stray code tags to plain text. The UN General Assembly 2024 pair works differently and was specifically checked during the 2026-08-09 report pass: `2024-09-24-milei-debate-general-del-79-periodo-de-sesiones.md` (the Spanish original) carries an explicit `duplicate_of: "2024-09-24-milei-un-general-assembly.md"` frontmatter field and a note stating it is intentionally *not* re-annotated line-by-line "to avoid double-counting a single speech event twice." Verified directly: this file contains zero live `[CODE: ...]` tags (its two matches for the string `[CODE:` are both inside prose explaining the convention, not actual tags) — so it does not, in fact, double-count anything, and the corpus's 194 physical coded files correctly represent 193 distinct speech events for statistical purposes. This file is also one of the 18 still-affected by the excerpt-omission bug (Section 6.1), which is a separate, still-open issue for this particular file (it uses "a non-standard bilingual (English/Spanish cross-reference) format, not the normal coding structure," per the audit's own note on why it resisted automated reconstruction).
